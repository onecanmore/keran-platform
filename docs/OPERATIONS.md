# 管理操作手冊

## 角色與安全
會員資格與員工角色獨立，同一會員可同時有有效志願者認證及援助方案。首次管理員用 `bootstrap_admin` 安全建立；沒有硬編碼共用密碼。`/admin/settings/` 授予需要的最小角色，必須重新輸入密碼及原因，不能自己改自己的授權。正式模式要求 `/account/security/` 註冊及驗證 TOTP。

- admin：設定、草稿內容、指派與報表；不能無日誌改歷史款項。
- reviewer：審核、額度、確認需求、資源配置；不得審自己的案件／認證。
- caseworker：只看自己被分派的個案，記聯絡及任務，無批准權。
- warehouse：庫存、資產檢查、必要履約資訊，不讀求助證明。
- merchant：只看自己 Suborder 的商品、交付及企業對帳，不讀其他商家或援助資訊。
- finance：獨立捐款報表、退款、支出及對帳，不讀求助證明。

伺服器再次驗證每項操作；看到導覽不代表取得權限，直接 API 越權也會拒絕。

## 商品與庫存
1. `/admin/partners/` 新增商家／機構，記聯絡、服務範圍及合作條件；協議未確認保持 draft，不填虛構比例。
2. `/admin/catalog/` 新增商品，設定實物／服務／申請物資、來源、單位、JSON 規格及價格（美分）。照片可上傳 PNG/JPEG/WEBP ≤5MB；未知圖片不要假冒真實，相關商品保持草稿。
3. 送審。發布前必須有照片、用途／安全確認、完整規格及政策；實物還要有已核准商家、價格、履約方。未完整的八類初始商品無法公開售賣。
4. `/admin/inventory/` 新增批次（先為0），依單位、擁有方、倉庫／倉位和用途池記錄。按「入庫／檢查」輸入 on-hand delta、hold delta 及原因。不得把待檢查商品標成可用。
5. 五臺代步車在逐臺資產區先檢查，再憑核准免費方案預留；交付要記收件人確認。未檢查不能預留，不能先搶先得。
6. CSV 匯入欄位：`lot_id,delta,hold_delta,reason`；最大1000列、1MB，全批交易，失敗不部分入庫。匯出使用同頁 Excel。舊倉庫 API 尚未接入。

## 求助與認證
1. 會員在 `/help/new/` 提出多類及多項需求，故事授權預設不勾選。可保存草稿，登入後提交；初次不要求完整住址或證明。電話／電郵核實目前明示待人工跟進。
2. 案件工作臺列出相同篩選明細，點案件進入處理。指派個案人員；聯絡記錄區分內部／會員可見。私人圖片證明透過短效下載，倉庫、財務及商家無權存取。
3. 審核員更新狀態及理由，確認每項需求的 confirmed 數量。收到、安排及已交付分開；轉介不是完成。
4. `/admin/finance/` 先以來源憑證建立已到位預算；案件頁批准 credit／free／discount，限制品類（逗號分隔）、期限、來源、件數及原因。無資金不可批准可花用額度；同家庭重複方案須人工例外原因（API）。
5. `/admin/plans/` 新建計畫並連結原 Need，不複製數量。從已確認援助用途批次預留；交付後點「確認已交付」，更新 fulfilled。過期未領取由 jobs 釋放；不把 approved 當成已完成。
6. 對外計畫摘要必須單獨經另一人審核，僅用人工匿名彙總，不帶出原始留言或地址。
7. 志願者在 `/verification/new/` 申請。於 `/admin/verifications/` 看說明及私密證明，人工決定並寫理由；有效期需先設定，未設定不能批准成永久。

## 訂單與履約
購物車只收已發布實物，淨水器／申請物資不混入支付。伺服器重新報價，採最低符合資格價格，支持額度不抵運費／稅。商家＋履約方拆 Suborder。

測試付款在清楚標示的 sandbox 頁完成，沒有卡號、真實扣款或真實寄信。付款成功後會員可產生一次性自提碼，倉庫／該商家輸入核銷；第二次拒絕。配送須確認地址及 tracking／交付證據；出庫發生在交付／發貨時，不在建立訂單時。

未付款可以取消，15分鐘預留到期由 jobs 釋放庫存及額度；重跑不重複恢復。已支付退款走財務核准＋可信測試事件，按比例退原現金及限制額度，不能換現。訂單明細 UUID 由「明細」查看；退款頁分別輸入 cash 和 aid 美分。運費／稅費獨立退款透過 API（order_id,shipping_cents,tax_cents,amount_cents），不能大於原收取金額。

## 眾籌
1. `/admin/fundraising/`「新增公益眾籌」填雙語、封面、目標（美分）、紐約時間、預算 JSON、匿名受助描述、執行安排、同意依據及完整政策。建議金額用整數美分陣列。
2. 提交 → 另一審核員核准 → 發布。未審核不能 checkout。若編輯重要內容，先 pause，再編輯為 draft，必須重新審核，舊捐款政策快照不變。
3. 公眾在項目頁讀政策後測試單次捐款；匿名預設開啟，V1 不公開姓名／留言。實收測試統計僅來自成功事件，成功跳轉本身不算入帳。
4. 達標後不再建新 checkout；已建立會話並發成功可能超募，仍完整入帳。截止由 jobs／checkout server 時間檢查，遲到成功標 needs_review。
5. 項目取消保留歷史，把成功捐款列待處理並排入通知 outbox。由財務依原政策核准退款，不默認變更用途。
6. 新增進展先存草稿，再由另人核准公開。支出依 submitted → approved（預留）→ paid（外部憑證）→ reviewed public（僅類別彙總）。不公開受款個資。

## 財務與報表
公眾捐款、商品款、企業預計及實收捐款分開。`/admin/donations/` 可依項目／狀態／日期 API 篩選，核准退款後到 `/admin/finance/` 模擬支付成功或失敗；只有成功才改實收。對帳必須附外部憑證及原因；費用不再從已扣費結算重扣。已退款／拒付及核准待退部分保留資金，避免超支。

Excel 與在線列表共用同一權限、條件及日期欄位；金額以美分呈現，不能混加不同資金 bucket 或數量單位。頁面合計可使用同一 report API 的 totals，XLSX 原始整數可自行核對。所有報表的日期口徑是 created_at；開始及結束日期按紐約本地日界（含結束日），已測試23／25小時夏令日。

## 通知、保留及工作
Outbox 記錄排程與重試；現僅 sandbox_recorded，不表示已寄信。每日／每分鐘跑 `run_jobs`，檢查釋放、認證到期、眾籌截止及附件清理。`retention_days` 尚未設定時必須視為上線阻塞，而不是推定永久保留。設定只影響新附件；既有附件改期限須經保留政策確認後維護處理。

任務可指派負責人及期限；本人更新狀態和服務分鐘，審核服務時數不可自己批准。後臺顯示實際待辦／逾期／需求地區分布與缺口，可點擊相同條件明細，不排名人的價值。
