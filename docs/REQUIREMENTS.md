## 3. 使用者角色與權限
會員資格與員工角色分開建模，多對多授權。預設拒絕，所有授權在伺服器驗證，不能只隱藏按鈕。

| 角色 | 可操作 | 不可操作 |
|---|---|---|
| 訪客 | 瀏覽、填寫求助草稿、合作表單 | 查看他人個資、直接領取 |
| 會員 | 自己訂單、自己的申請、認證及預約 | 他人案件或訂單 |
| 認證志願者會員 | 上述加指定購物禮遇 | 自動取得後臺權限 |
| 個案志願者 | 分配給自己的案件、聯絡紀錄、待辦 | 批准援助、查看全庫敏感資料、財務 |
| 審核員 | 評估、批准／拒絕、覆核、方案額度 | 自己批准自己的申請 |
| 倉庫／配送 | 揀貨、出入庫、必要地址與聯絡資料 | 收入、健康或困難證明 |
| 商家 | 自己商品所涉履約與結算 | 受助身分、證明、其他商家資料 |
| 財務 | 捐款對帳、支付退款、結算與財務匯出 | 非必要申請附件 |
| 管理員 | 設定、角色、任務分派、內容發布、報表 | 無日誌修改歷史款項 |

任何利益衝突案件改派其他審核員。高敏操作需再次確認並記錄原因。初始管理員安全建立，不交付硬編碼共用密碼。

## 7. 志願者認證與價格規則
預設人工認證：機構名稱、服務說明、可選證明、聯絡同意；可由合作機構確認，也可人工評估無機構證明者。此為建議預設，可由管理員修改。
狀態：submitted、under_review、needs_info、approved、rejected、expired、revoked。
有效期由後臺設定；未設定不得假定永久有效。拒絕提供理由與覆核入口。
所有購物會員均可購買公開商品；有有效認證才取得志願者優惠。

價格計算：
1. 選出有效公開價及符合資格的志願者／關懷價格方案。
2. 預設優惠不疊加，使用可用方案中最低價格；關懷額度可支付批准範圍內的折後金額。
3. 額度不得產生負數或現金找零；運費及稅費是否可抵，由方案明確設定，預設不可抵。
4. 沒有批准的關懷資格，不能由前端自行選擇免費價格。
5. 價格、資格、庫存、運費及稅費在伺服器重新計算；付款前過期必須重新確認。
6. 訂單保存價格及規則版本快照，後續改價不回寫歷史。
7. 測試價格只存在 demo seed，與正式資料隔離並清楚標示。

## 8. 開放需求徵集
入口文案：「告訴我們您的需要，即使商城目前沒有，也可以提出。」
欄位：
- 申請身分：自己／家人／經同意代申請／機構轉介；代申請保留同意記錄。
- 地點：州、市、ZIP；第一步不收完整住址。
- 需求分類（多選）：食品飲品、衣物保暖、家居用品、行動出行、老人陪伴、數位設備協助、其他。
- 每一需求項目：名稱、數量、計量單位、供幾人使用、用途、是否可接受替代品。
- 希望時間：幾天內／兩週／一個月／長期，必要時具體日期。
- 持續性：一次／短期／持續。
- 留言：困難及最有用的支持；限制長度、提示不要填 SSN 或不必要病歷。
- 取得方式：自提／配送／到場服務／不確定。
- 電話或電郵至少一項、偏好語言、方便聯絡時間。
- 附件選填，私人保存；所需證明於具體援助階段再請求。
- 聯絡、機構轉介、公開故事三項同意分開；公開故事預設不勾選，不影響援助。

可先填寫草稿，再驗證聯絡方式提交。若電話驗證供應商未接入，明示待人工核實，不偽造驗證成功；提供電郵或人工協助途徑。驗證方式避免暴露帳號是否存在。
提交回傳案件號；可登入或經安全驗證查看，不能僅憑可猜案件號讀取。
提示：申請不代表獲批，依資源及範圍評估；非即時緊急救援入口。
超出區域的需求可記錄但標示超出首期範圍，不承諾提供服務。
允許補充、撤回；對過期候補需求發起人工重新確認，未確認者不算有效缺口。

## 9. 案件、援助與服務流程
案件狀態：
received → reviewing → matching → arranged → completed。
輔助狀態：needs_info、waitlisted、referred、declined、withdrawn。
所有轉換記錄執行者、時間、理由；退回／重開須記錄理由。referred 不等於完成；拒絕或暫無資源提供說明及覆核入口。
個案志願者記錄聯絡與提出建議，審核員決定援助。無自動 AI 評分或拒絕。
需求、援助批准、實際履約分別建模，批准本身不扣掉「已完成」需求。
支援部分安排、部分交付；每個需求明細記錄 requested、confirmed、allocated、fulfilled 數量與單位。
一案可有多筆援助，不能僅以案件一個狀態取代明細數量。

援助方案：
- 指定商品優惠；
- 免費物資限定件數；
- 限商品／品類、期限及金額的支持額度；
- 特殊物資，需再次適配及交付確認。
保留審核者、原因、資金／物資來源、上限、有效期及預算預留。
額度 available = granted − redeemed − reserved − revoked；退款用沖銷記錄恢復原資金來源，不能變成現金。
方案可禁止重複領取，設定按家庭、商品及期間限制；需人工例外時保留理由。
審核批准須有可用預算或標待資金，不能發出無資金支持的可消費額度。

淨水器預約狀態：submitted、contacting、quoted、scheduled、completed、cancelled；報價／合約由指定人員確認，預約表不可承諾已簽約。
代步車逐臺資產號，檢查合格後才可預留，交付需收件確認；不採先搶先得。

## 10. 庫存、購物與履約
每個實物 SKU 明確計量單位，箱、件、瓶不可直接相加。不同包裝換算需明確設定。
庫存按擁有方、倉庫、倉位、批次、用途區分；庫存日誌不可直接覆寫。
on_hand：實際在庫；reserved：已預留；hold：待檢查／隔離；available = on_hand − reserved − hold。
混合用途採獨立數量池或有稽核的用途移轉，不得同時承諾同一件商品義賣和免費發放。
接受捐贈記錄用途限制，受限制物資不能自行改為義賣。
訂單預留、支持額度預留及釋放以資料庫交易執行，禁止超賣。
普通付款預留建議15分鐘可配置；援助領取期限另行配置；到期釋放與通知必須可重試及具冪等性。
遲到付款成功但預留已釋放：重新嘗試配置，失敗轉人工處理／退款，不得默認已可履約。
庫存出庫在實際交付／發貨時扣 on_hand 並釋放預留。取消釋放；退貨檢查後決定可再售、隔離或報損。
食品預留批次與有效期欄位，過期或隔離批次不得可售。

購物車按銷售方及履約方拆成子單，運費、交付與退貨各自呈現；主付款與子單分攤可對帳。
訂單分開保存 payment_status、fulfillment_status、refund_status，避免一個狀態表示全部。
零元物資訂單不呼叫支付接口，但經後臺核准及身份確認，仍有完整庫存和履約紀錄。
自提核銷碼不可猜測、一次性且可撤銷；同一碼不得重複出庫。配送記錄必要聯絡資料與完成確認。
運費由 ZIP、方式、商家規則配置；無法配送應在付款前提示。
稅費按已確認稅務方案接入，未完成正式配置禁止真實付款，不把未知稅額設為0。含補助及退款的稅基交由正確規則／提供者處理。

## 11. 企業、捐款與財務
企業檔案包括聯絡人、可供品項、履約範圍、協議附件、有效期、上架審核與捐款規則。
捐款可設每件固定金額，或合資格淨商品銷售額比例；不得使用未定義的「部分利潤」。
捐款基數預設扣折扣及退款、不含稅與運費；基金會支持額度支付的部分預設不計入商家捐款基數，避免循環計算，特殊協議另設並說明。
每個訂單項保存適用基數、比例／定額、規則版本與預計金額。部分退款按相關明細重算差額並作沖銷，已結算款項以調整單處理。
狀態：estimated、pending_settlement、receivable、received、adjusted。
「已收到捐款」必須有收款確認、日期與憑證；不能把付款訂單自動算成實收捐款。
商品款、平臺服務費、支持資金及企業捐款分開帳本，保存交易關聯 ID。金額以美分整數儲存、幣別 USD，不使用浮點金額。
商家結算預設人工對帳／核准，未具合格支付分帳配置不實作自動付款；不得默認基金會可以代所有商家無限制收款。
結帳明示實際銷售主體；購物收據不自動當成使用者捐款收據。平臺費、捐款比例、銷售主體、稅務與協議均列上線前配置項。
付款採託管結帳，不儲存卡號；Webhook 驗簽、事件 ID 唯一、防重複處理，價格不能信任瀏覽器。

## 12. 幫扶計畫與資源匹配
可將多份已確認需求連結到計畫，不複製原案造成重複計數。
計畫欄位：名稱、服務地區、類別、受助戶數、需求明細及單位、已有資源、缺口、負責人、預算、合作企業、期限、執行與完成記錄。
狀態：draft、internal_review、approved、active、completed、cancelled。
對外展示需單獨發布審核；僅顯示匿名彙總，不含原始留言、聯絡方式或住址。
未核實需求與已核實需求分開。企業透過合作表單承諾供應後，仍需確認收到／可用，不能當作現貨。
案件關聯物資、服務預約或訂單後，自動更新已安排數量；交付後更新 fulfilled，人工更正需留痕。

## 13. 工作與統計中心（V1.0 核心）
首頁：今日待辦卡片、逾期提醒、需求分布、資源缺口、快捷指派。不得用裝飾性假圖表。

每張卡／圖表可點擊帶同篩選進入明細；明細支持在線分頁、排序、必要的工作操作及 Excel 匯出。匯出與查看必須同權限。

### 統計口徑
- 全部時間存 UTC，展示和日／週／月篩選按 America/New_York，處理夏令時間。
- 新案按 submitted_at；完成服務按 fulfilled_at；實收捐款按 received_at，介面明確顯示。
- 家庭以 household_id 去重；無法確認同戶時標待核對，不只靠地址自動合併。
- 同一人多角色不重複計新增會員。受益人數無可靠個人資料時標示「家庭回報人數估計」，不能宣稱已去重實際人數。
- 淨商品銷售額 = 已收商品金額 − 商品退款，不含稅運費；支持額度支付單列，不當成新增現金收入。
- 未履行需求 = max(confirmed − fulfilled, 0)；未安排需求 = max(confirmed − fulfilled − allocated, 0)。
- 可供匹配庫存只計相容商品、相同單位、可用用途池及服務地區；缺口 = max(未安排需求 − 本次分配可用供給, 0)。同一供給不可在多個計畫重複抵扣，匹配分配需原子化。
- 無明確商品或單位的需求顯示待匹配，不能強行計算缺口。
- 首次回應排除自動收件信；平均完成時間以已完成案件計，並顯示樣本數。逾期按 next_follow_up_at，未設不得捏造逾期。
- 跨狀態統計防止多表 join 重複加總；所有總額須能與明細對上。
- 公開成果排除測試、撤回、未履約及僅轉介案件；小群體敏感統計可合併隱藏，預設少於5戶不公布精細地域交叉資料。
- 匯出保存篩選條件、時間與操作者；Excel／CSV 防公式注入，敏感欄位依權限遮罩。
- 批次指派、更新跟進時間、生成揀貨單可用；不可不經逐案核准而批量批准援助。

## 15. 技術與 API 實作要求
技術建議（非強制）：TypeScript 全端、React、關聯式資料庫 PostgreSQL、私有物件儲存、伺服器端認證。如既有環境有可靠等效技術則沿用，不為套用技術重寫。
正式資料不得只用 localStorage 或記憶體陣列。金鑰只放伺服器環境變數。
核心 API 能力：
- catalogue/search、checkout/quote、checkout/create、orders、refunds；
- verifications、help-requests、need-items、case-transitions、aid-grants；
- stock/reserve、stock/release、stock/fulfill、stock/return；
- appointments、plans、allocations、tasks；
- reports/summary、reports/detail、reports/export；
- payment/webhook、finance/reconcile、settings。
API 統一驗證、分頁、錯誤碼；對敏感 mutation 支援 idempotency key。重複請求不重複扣款、扣額度、出庫或入帳。
通知採 outbox 或等效可靠機制，實際發送非交易成功的唯一條件；失敗可重試、顯示狀態。不在電郵／簡訊包含困難證明。
可配置通知：收件、補件、審核結果、預約、自提／配送、候補更新。原型測試寄送隔離，禁止給真實使用者群發測試信。
必要保護：登入限流、CSRF／XSS 防護、附件型別／大小驗證及安全檢查、短效私密下載連結、管理帳號 MFA（生產）、權限稽核、避免日誌記錄敏感附件與金鑰。
資料保留天數需上線前確認；提供配置及到期清理工作，不擅自永久保留證明。
提供環境變數範本，不含真實秘密；備份、還原、遷移及故障處理說明。生產前實作一次還原驗證。
如使用外部套件／支付／登入服務，開發時查核其官方當前文件及執行環境相容性。

### 20.1 目的與範圍
基金會管理人員在後臺自行建立及發布公益項目，公眾在網站直接捐款，基金會追蹤實收款項、項目支出及幫扶成果。
V1.0 採單次捐款、USD；不要求捐款人註冊購物會員，不提供投資、利息、回報、抽獎或商品交換。志願者與受助者不必捐款才能取得服務。
可以從已確認的求助需求或幫扶計畫建立眾籌，也可獨立建立基金會公益項目。眾籌與求助個資分離，發布必須審核，不自動轉貼求助留言。
款項只進入經確認的基金會收款帳戶，不直接轉給申請者，也不與商家商品款混用。基金會法律名稱、組織狀態、捐款憑證文案及可抵稅表述須核實；系統不得自動宣稱已獲501(c)(3)認可或捐款一定可抵稅。

### 20.2 後臺自主發布功能
新增 /admin/fundraising，清楚提供「新增公益眾籌」按鈕，可管理：
- 標題、中英文摘要及正文、封面與相簿、類別、服務地區、公開 slug。
- 目標金額（美分正整數）、開始／截止時間、資金用途及分項預算。
- 受助對象匿名描述、預計服務家庭／人數（標示預計）、執行安排、負責人。
- 關聯幫扶計畫／需求、發布同意依據、內部審核資料。
- 建議捐款金額與自訂金額上下限；上下限可配置並由伺服器驗證。
- 未達標、超募、取消、剩餘資金及退款政策；必填並在付款前可閱讀。
- 進展更新、支出記錄、已完成成果、結案報告。
流程：draft → submitted_for_review → approved → scheduled/published → paused/closed → completed；亦可 cancelled。
編輯者提交，具發布權限人員核准；已發布項目的目標、用途、期限及政策屬重要變更，須重新審核並保留版本。已捐款者的同意依原政策快照保留，不能追溯變更資金限制。
截止工作、到期暫停、手動暫停均須伺服器控制；停募後保留項目與進展頁，不刪除捐款歷史。

### 20.3 前臺頁面
新增：/fundraising（公益眾籌列表）、/fundraising/:slug（詳情）、/fundraising/:slug/donate（捐款）、/donations/result（結果）、/account/donations（我的捐款）。
首頁與導覽加入「公益眾籌」入口，購物與求助主入口仍保留。
項目詳情展示：目的、目標、期限、已確認捐款、進度、受助群體、預算用途、執行安排、更新、政策和聯絡入口。
進度條超過100%時以100%視覺填滿並清楚列出實際百分比，不截掉超募金額。不得添加虛構捐款人、倒數或初始籌款額。
捐款頁提供建議金額、自訂金額、收據電郵、收據所需姓名、可選留言及「公開匿名」選項；公開匿名預設開啟。匿名只指對外不顯示姓名，不代表支付服務不留交易資料。
V1.0 不公開捐款人名單及留言，僅顯示彙總數據；內部財務仍可按權限查看收據與對帳資訊。行銷訂閱另行選填，不能綁定捐款。

### 20.4 支付、確認與收據
捐款與購物使用獨立業務類型、訂單／交易關聯和對帳分類，不能放進同一購物車。
託管支付頁、伺服器建立金額、驗簽 Webhook、冪等與重試要求同購物。捐款狀態：initiated、pending、succeeded、failed、cancelled；退款及爭議狀態分開記錄。
瀏覽器跳轉成功不是入帳依據；只有已驗證的支付成功事件可計入已確認捐款。延遲付款顯示「確認中」。
每筆成功捐款發送一次捐款確認／收據（可人工重發），含交易號、項目、日期、金額、基金會經核實的法定資訊；電子郵件失敗可重試，不造成重複收款。
捐款人可經帳號或短效安全電郵連結查詢與下載自己的確認文件；不可只憑可猜交易號查詢。發生退款後提供對應更正記錄。
支援信用卡／其他方式以實際支付服務可用性為準。缺憑證時以清楚標記的 sandbox 演示，停用真實捐款，不偽造實收。

### 20.5 達標、超募、截止及取消的明確規則
V1.0 預設為「彈性募款」：款項成功即收取，不等待達標；此規則須在付款前清楚說明。未達標如何縮減或延後執行由項目事先寫明；未填妥政策不得發布。
預設達標後暫停建立新捐款結帳，不作嚴格硬上限保證。並發成功或已建立結帳後成功可能造成超募；仍須接受入帳、列出超額、依事先政策處理，不漏記或擅自轉移。
每個待付捐款保存項目政策版本與結帳有效期；項目暫停／截止時盡量關閉未付會話。若仍收到遲到成功事件，計入帳並轉待處理，依原政策履行或退款，不直接忽略。
只有經核准且事先披露用途的項目才可設定持續超募。取消或無法執行時建立待處理清單、通知捐款者並按政策退款／取得另行用途同意，不能默認改作無關用途。
完整或部分退款須經財務核准、原支付渠道執行，Webhook 確認後更新金額；退款失敗不可先扣掉已收款統計。退款理由、處理者及外部交易ID留存。
爭議／拒付保留事件紀錄、凍結待處理金額，結案後作沖銷或恢復，不重複扣款。

### 20.6 資金帳、用途與統計口徑
新增「公眾捐款」獨立報表，不能與企業銷售捐款、平臺費、商品款或支持額度混加。
按項目、日期、狀態篩選；可點擊到明細及匯出 Excel。財務明細包含成功總額、已退款、已結案拒付、待處理爭議、支付費、實際結算、支出與剩餘可用資金。
公開已確認捐款 = 成功捐款總額 − 已成功退款 − 已確認且未恢復的拒付本金；尚有爭議金額另列待處理，不當作可支用。
公開進度 = 已確認捐款 / 目標金額；清楚標示未扣支付處理費。實際到銀行的金額另列結算，不將支付成功誤稱銀行已到帳。
內部可支用額 = 已結算可支用資金 − 已支付項目支出 − 已核准預留支出 − 必要退款／爭議準備；不得重複扣已包含於淨結算的費用。
捐款筆數以成功交易ID計，不稱為捐款人數；確需人數須使用一致的捐款人識別去重，無法確認則不公布。
支出記錄：項目、用途類別、受款方、金額、日期、憑證、批准者及付款狀態。公開頁僅呈現經審核的彙總及遮罩憑證，不暴露個資。
每個項目建立受限用途帳本，退款、用途調整、支出採追加與沖銷；財務可對帳至支付服務交易及銀行結算。

### 20.7 新增資料與介面
fundraising_campaigns：目標、期間、公開內容、狀態、負責人、關聯計畫。
campaign_policy_versions：版本、彈性募款／超募／取消／退款／剩餘資金政策、審核。
public_donations：campaign_id、donor_reference、amount_cents、currency、政策快照、付款狀態、收據資訊與公開設定。
donation_refunds / payment_disputes：原因、外部ID、金額、事件與狀態。
campaign_ledger / campaign_expenses：資金來源、費用、結算、支出、預留、沖銷關係及憑證。
campaign_updates / donation_receipts：更新發布審核、收據版本及通知狀態。
Webhook事件可沿用 payments 表但必須明確 payment_purpose=public_donation / commerce；企業捐款與公眾捐款不可混用同一統計欄位。
新增API能力：campaigns CRUD/submit/approve/publish/pause/close、donation-checkout、donation-status、donation-refund、campaign-expenses、fundraising-reports。所有敏感操作要求伺服器端權限與稽核。

### 20.8 增補驗收 A31–A42
| ID | 情境 | 通過條件 |
|---|---|---|
| A31 | 管理員新增商品 | 無需改程式即可上傳圖片、設定規格價格庫存、送審及上下架 |
| A32 | 新建公益眾籌 | 後臺建立、審核、發布，前臺可見且可進捐款流程 |
| A33 | 未審核或停募項目 | 不能直接以API建立有效捐款結帳 |
| A34 | 改金額或假成功跳轉 | 伺服器驗證，不變更實收及公開進度 |
| A35 | 重送支付事件 | 只產生一次入帳、一次自動收據及一次進度更新 |
| A36 | 部分退款及失敗退款 | 成功退款正確調整；失敗退款不提前改實收 |
| A37 | 並發達標、截止後遲到付款 | 無漏帳，按政策轉處理，介面顯示真實超募 |
| A38 | 公開匿名與資料權限 | 不公開姓名留言，其他會員或志願者無法讀捐款者資料 |
| A39 | 項目取消 | 可列受影響交易、通知、核准退款並追蹤結果 |
| A40 | 商品／企業／公眾捐款 | 三種來源各自統計、可核對，無混計或重複 |
| A41 | 進度與對帳 | 明細、報表、退款、費用、結算及支出一致 |
| A42 | 無正式收款配置 | 可測試演示，真實捐款停用，無虛構已到帳宣稱 |

### 20.9 開發與上線補充
在階段三加入眾籌付款、退款及收據，階段四加入項目公開頁與捐款報表，階段五驗收A31–A42。
上線前由基金會確認法律收款主體、支付服務支援、募款可接受區域、相關登記要求、捐款聲明與項目政策；首期服務NY/NJ不代表已授權全美募款。將這些作為可配置的真實收款啟用條件，先完成程式與測試，不自動推定法律結論。
完整完成定義增加：管理員可自行上架商品、發布公益眾籌；公眾能安全完成捐款並取得確認；基金會可核對款項、依法定及承諾用途使用、退款並發布真實進展。總驗收案例更新為42項。
